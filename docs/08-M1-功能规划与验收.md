# 净界 M1 功能规划与验收

基线：GitHub `MozzXLay/mind-guard` 的 `ea4039b`。目标：从 M0 的安全外壳进入真正可每天使用的离线闭环：记录 → SOS → 小行动 → 回顾。M2 浏览器扩展、屏蔽规则、托盘、开机启动和正式发布包不属于 M1。

## 1. 前置切片 M1.0：守住现有 M0 数据

1. 修复自动锁定对系统时间回拨的依赖；窗口后台/挂起恢复时重新核对后端锁定状态并立即遮盖敏感 UI。
2. 先设计并实现 v1→v2 事务迁移，保持 `0001_initial.sql` 不变；在实际 M0 加密库中导入真实目标后升级，确认目标未丢失。新用户应用完整迁移链。升级失败不留下半张表或半个版本号。
3. 提供当前库打不开时的备份恢复入口，验证候选备份密码、AEAD、SQLCipher 和 schema 后再改文件；保留旧库以供撤销，错误密码及损坏备份绝不覆盖原数据。恢复 v1 备份时走版本升级。
4. 修复 manifest/database 单边存在的初始化状态；不删除用户原件来“重试”。

验收：M0 数据原样打开 M1；损坏库可由备份恢复；系统时间回拨/挂起后敏感 UI 被遮盖；模拟迁移中断旧库仍可恢复。

## 2. M1.1：事件记录与今日

### 事件模型

`behavior_event`：随机 id、`type`（`urge`/`viewed_content`/`stopped_viewing`/`masturbation`/`alternative_action`）、`occurred_at_utc_ms`、`zone_id`、`local_date`、`local_hour`、可空 `intensity`（0–10）、可空 `duration_sec`、可空 `note`（<=2000 字符）、`created_at`、`updated_at`。`event_trigger`：`event_id` + 枚举 code，唯一复合键。`local_date`/`local_hour` 由 Rust 按事件发生时区导出，避免数据库按当前时区重算历史日期；时间戳包含偏移/时区校验。普通自慰与所谓“失败”没有默认映射。无网站 URL 或图片字段。

Rust command：新增、列表（时间范围/类型/分页）、详情、更新、删除；所有操作先校验解锁状态、类型、时间、备注长度与强度范围，使用参数化 SQL 和事务。删除后统计从现存事件计算。返回错误码和可读提示，不暴露正文到日志。

UI：今日真实概况和最近记录，记录页的空态/列表/筛选/编辑/删除，十几秒即可保存一条记录。事件发生时间支持补记、编辑；操作成功后首页与洞察同步刷新。优先做录入与正确性，再做视觉细节。

验收：从空库新建“昨晚 23:30 浏览，压力+疲劳”，改成“主动停止”，两处列表与统计同步；跨午夜、DST/时区切换和删除后统计不重复、不串日；锁屏内容立即消失。M0 已有目标仍可读取。

## 3. M1.2：目标与小行动

保留已有 `goal` ID 与历史，补编辑目标标题/状态（active/paused/archived），不依赖标题作为主键。`plan_action` 对应目标，字段 id/title/enabled/frequency 或明确的每日频率；`action_completion` 记录 action_id/本地日期/发生时间。一天一次的计划项应有唯一约束，重复点击幂等；停止目标不删除历史。首页展示今日小行动与真实完成数。保持“自慰不默认算失败”和提醒默认关闭。

验收：可新增/编辑/暂停目标，勾选→取消→重勾选小行动后当日计数正确；重启、备份恢复后结果一致。

## 4. M1.3：可保存的 SOS

沿用 M0 的 90 秒无需记录模式作为锁定页入口，**保持匿名且不落盘**。解锁状态下提供可选保存版：开始时间、初始/结束强度（可跳过）、状态（进行中/已跳过/已中断/已结束）、替代行动（可不选），`urge_session` 存储。呼吸计时可暂停/跳过/退出；不写虚假强度、不强制结束或奖励。窗口关闭/锁定时将未完成会话安全标记为 interrupted 或明确丢弃，不能悬空成“成功”。

验收：锁定页 SOS 无持久化；解锁状态 30 秒跳过、第二次强度留空能保存；恢复备份后会话可查；减少动态效果模式可用。

## 5. M1.4：日记与洞察

日记：`journal_entry` 的新建、列表、正文查看、编辑、删除；标题可为空、显示日期与安全截断摘要；无需联网。建议正文上限例如 10,000 字，边界在 Rust 强制；保存时不要通过 console、错误消息或文件名泄露内容。锁屏时卸载编辑器和缓存。

洞察：近 7/30 天的有记录日数（分母 7/30）、分类型事件次数、SOS 次数、触发因素计数、小时分布。统计基于真实数据；平均强度只用非空样本并显示样本量；多个触发因素可同时计数，不把其比例相加当作 100%；样本少于 5 条时仅展示原始计数，不给“主要触发”结论。注意被浏览器拦截次数是 M2 才可能存在，M1 不伪造。

验收：空库清晰空态；一个事件与 30 天跨界的边界正确；编辑/删除后图表与数字更新；10 万条模拟事件的 30 天统计目标 <2 秒，注明测试机配置。

## 6. 数据与流程约束

- 明文仅存在运行内存；数据库、journal、备份、临时文件继续加密。允许日志记录错误码、表名和操作时长，不记录事件备注、日记、密码或访问 URL。
- 前端只经窄化 Tauri commands；对输入的服务端校验、分页与 SQL 参数绑定在 Rust，不能依赖 React 校验或本地存储。
- M1 迁移版本和备份文件版本分别处理；恢复旧备份、更新到 M1、锁定、重启后仍可解锁。恢复成功后清理 React 缓存、重新拉取全部状态。
- 解锁时统一处理迁移耗时与失败反馈；备份和恢复与迁移不得并发使用同一库。避免长任务占用锁导致 UI 假死。
- 完成一片后提交可审查的独立 commit；本地用户数据绝不纳入 git；不要自动推送或重写 `main`，留给用户检查。

## 7. 建议验收矩阵

| 场景 | 期望 |
| --- | --- |
| M0 v1 密文库升级到 M1 | 目标与密码可用，schema 变为 v2，旧库失败可恢复 |
| 创建/编辑/删除事件与触发因素 | 日期、列表、今日、7/30 天洞察同步 |
| 23:30 补记、跨日、时区/DST | 保留原发生地日历归属，历史结果稳定 |
| 目标暂停与行动重复勾选 | 当日完成数不重叠，历史保留 |
| 锁定时 SOS / 解锁时 SOS | 前者绝不保存，后者允许跳过并保存可选评分 |
| 日记锁屏 / 自动锁 / 时间回拨 | 正文不在界面保留，后端拒绝无密钥命令 |
| 健康库 / 损坏库 / 新安装恢复备份 | 可预览并恢复；错误密码或损坏文件不覆盖 |
| 空库 / 小样本 / 10 万事件 | 没有虚构指标，性能与样本量可验证 |
