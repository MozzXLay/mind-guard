# M0 安全决策与威胁模型

状态：M0 实施决定，2026-09-27。此文描述实际边界，不能替代独立安全审计。

## 保护对象与边界

目标、未来的事件与日记、数据库页、备份及主密码属于敏感数据。对手模型包括：能读取关机设备上用户数据目录的同机用户、拿到备份文件的人、误填密码的人。已控制当前登录会话、读取进程内存或注入 WebView 的恶意程序不在本方案的抵御范围。没有服务端恢复密钥；忘记主密码意味着旧库不可恢复。

## 存储决定

1. Rust 是唯一持久化入口。前端只调用窄化的 Tauri commands，不持有 SQL 能力。首次创建库前先生成随机 32 字节数据密钥，以 SQLCipher 原始密钥模式加密整个 SQLite 库。运行时检查 `cipher_version`，缺失时拒绝创建和打开；不回退明文 SQLite。
2. 主密码用 Argon2id v19 派生包装密钥，初版参数为 64 MiB、3 次迭代、1 lane、16 字节随机盐；参数写进版本化 `vault.json`，以后变更须迁移。使用 XChaCha20-Poly1305 包装随机数据密钥。密码只在当前请求中使用；锁定时丢弃并尽力清零内存数据密钥。Rust、WebView、系统交换区或崩溃转储中的复制不能保证全部清除。
3. `vault.json` 只含格式、KDF 参数、盐、nonce 和密钥密文，不含密码或用户内容。SQLCipher 打开后校验 schema 版本与 `integrity_check`。新数据库没有明文过渡阶段。敏感文本不得进入日志、错误、遥测或控制台。
4. 应用数据和备份目录设为 `0700`，文件用 `0600` 创建。使用 DELETE journal、内存临时表，避免 WAL 留存；同时由 SQLCipher 加密页。禁用 WebView 远程内容与外部资源，生产 CSP 只允许本地资源。
5. 备份是版本化 JSON 容器：内含当时的非秘密密钥元数据，以及用当前数据密钥经 XChaCha20-Poly1305 再加密的 SQLCipher 数据库字节。写入临时文件后 `sync_all`、原子改名。恢复先用备份密码解包、校验 AEAD、用 SQLCipher 检查库及 schema，再在同一目录替换；失败时回滚旧文件。M0 限制备份文件最大 128 MiB，后续大库需流式格式。

## 关键残余风险

- Argon2id 参数是 Ubuntu 开发机起点，发布前须在低配目标机测耗时与内存，并保持元数据版本兼容。
- SQLCipher 的 Linux 动态链接、打包产物、不同机器上的 openssl/crypto 依赖和密钥处理须在 M3 实测。不能因开发机运行成功就宣称发布包安全。
- 当前只完成最小备份恢复；跨盘原子性、断电期间的目录持久化、磁盘满和多进程并发恢复需后续故障注入。M0 使用单实例窗口，后续还需覆盖多个系统进程的竞争。
- 锁屏能遮蔽应用界面，但不能擦除窗口管理器先前保存的缩略图、交换区和外部截屏。密码输入在 WebView 中会短暂存在。

依据：[SQLCipher 原始密钥与验证](https://www.zetetic.net/sqlcipher/sqlcipher-api/)、[Argon2 Rust 实现](https://docs.rs/argon2/latest/argon2/)、[RustCrypto XChaCha20-Poly1305](https://docs.rs/chacha20poly1305/latest/chacha20poly1305/)。
