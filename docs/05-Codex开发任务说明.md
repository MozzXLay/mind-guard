# 交给 Codex 的开工说明

请以同目录的 `01-产品需求与验收.md`、`02-技术架构与数据安全.md`、`03-UI设计规范与页面交互.md`、`04-可交互UI原型.html` 为唯一产品基线，开发 Ubuntu 24.04 优先的 Linux 本地桌面应用“净界”。原型仅用演示数据，不含真实安全实现。

## 首个开发任务：M0

1. 创建单仓库 Tauri 2 + React + TypeScript + Rust 工程，开发环境在 Ubuntu 24.04 可运行；不要引入云服务、远程字体、遥测或账号。
2. 从原型实现设计令牌、响应式桌面壳、首次引导、锁定/解锁与今日空态。UI 使用真实控件状态，不直接把原型 HTML 嵌入 WebView。
3. 在任何真实敏感数据写盘之前完成数据库加密、主密码派生、密钥版本设计、数据目录权限、日志去敏和最小的加密备份恢复验证。先写出具体威胁模型和技术决策记录；SQLCipher/Stronghold 仅为候选，不可未经验证就宣称安全。
4. 写必要的验证：建库→退出→解锁；错误密码不可读；磁盘/日志中搜不到测试备注；备份恢复后数据一致；窗口窄屏与键盘流程。
5. 给出运行命令、打包先决条件、尚未完成的界面和风险。M0 验收后进入 M1。不要把 M2 扩展伪装成已工作。

## 后续切片

- M1：事件 CRUD、计划、SOS、日记、洞察，替换原型演示数据；从真实数据计算统计；保证空态与编辑后同步。
- M2：Firefox 扩展、宿主、缓存规则、拦截页、暂停流程与失联状态。先证实浏览器 API 与 Native Messaging 在目标版本上的行为。
- M3：Chromium、托盘、可选开机启动和快捷键、安装包；明确 X11/Wayland 差异。

## 每次提交前的完成定义

代码可构建；功能按照 PRD 验收；无敏感信息进入日志/明文临时文件；键盘可操作；空态/错误态可恢复；文档反映实际行为。若 PRD 与真实平台能力不一致，记录证据、提出替代方案并更新相应页面规范。
